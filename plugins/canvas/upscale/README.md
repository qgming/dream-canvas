# 超分节点

内置插件 `upscale` 提供 `upscale:media`，由服务端节点目录统一启停。应用启动时注册，前端源码由 Vite 按需加载，无需独立安装或构建。

- 每次处理一张图片或一段视频，可连接画布节点，或通过加号从资料库、画布及上传添加。多个源输入会明确提示，不静默取第一份，也不会取自身成品再次超分。
- 无提示词输入。提交空提示词后，服务端只为该类型节点补入保留主体、构图、风格及视频时序的默认超分指令；接口插件按自身契约决定是否传给供应商，显式 API 提示词不被覆盖。
- 模型来源于已启用的渠道目录及管理员排序，不猜供应商名称、不硬编码模型 ID；要求能力为图片或视频且有效模式下只有一个对应类型素材入口。声明 `mode` 时必须提供真实的 `upscale` 选项，未声明模式的单图编辑接口也可通过默认指令使用，但实际增强能力仍由模型决定。
- 只展示模型声明的 `resolution / scale / size / width / height` 目标字段，选项、建议、默认值及约束不另造一套；其他参数沿用管理员与接口默认值。需要额外必填项且没有默认值的接口会按既有校验报错，应由管理员补全默认配置。
- 连接的素材在该节点提交时显式绑定到唯一命名素材入口，或作为分类参考提交；不会改变普通视频节点首尾帧绑定。参数、连线与结果保存在现有项目业务中，生成使用同一任务系统、事件通知、取消与结果回填，不在关闭面板时取消任务或手动覆盖成品。
- 成品仍输出对应图片或视频资源，可接入其他节点，下载沿用真实原件 MIME 后缀逻辑。

不修改或发布现有接口插件。DMC 自建视频超分脚本与接口要求视频 URL 路径带真实扩展名；后端新保存规则在构建并重启后，为新上传和生成的媒体原件及私有云对象统一保留真实后缀，签名地址沿用同一文件名。已有文件不自动改名，管理员可在资产库手动确认「修复历史文件后缀（临时）」，等待素材使用中的任务结束，先保存及同步正确后缀，再切换稳定资产记录并清理旧副本；完成后可继续使用原资产及画布引用，无需重新生成。也可自行重新上传使用新资产。仅重试旧任务不触发后缀修复，不设为公开，不静默改写已发布脚本，也不保证所有原件格式均符合供应商限制；DMC 真实下载、超分及成品保存仍需独立验收。

代码实施与未验收项目见 [CHANGELOG](../../../CHANGELOG.md#unreleased)。
